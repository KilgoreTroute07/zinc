# Combined Libraries

1. [Commander](https://github.com/tj/commander.js) - The commander library is used to the create command line script that is actually executed and parses the actual command line inputs.
2. [Inquirer](https://github.com/SBoudrias/Inquirer.js) - The inquirer library is used to prompt the user of the created scripts for any necessary script input that was not supplied directly via command line arguments
3. [Zod](https://zod.dev) - Zod is used to parse, verify, and transform the given values for options that are then passed to the "action" function given to the generated commander script. This provides better type safety, and inference for the developer, and a more diverse and controllable parsing system for inputs.

# Usage

## ZincOptionCreators (Options)

Options are defined with **ZincOptionCreators**: `input`, `boolean`, and `select`. Each creator returns an option that can be chained with `.optional()`, `.silent()`, and (where applicable) `.default(value)`. Options are validated with Zod and can prompt the user via Inquirer when a value is not provided on the command line.

Import the creators from the option module:

```ts
import { ZincOptionCreators } from './option-creator';
import { z } from 'zod';
```

### Common Args

Every option creator (`input`, `boolean`, `select`) accepts these properties. They are primarily used for generating the underlying Commander option as well as default values for Inquirer prompts.

**Name**: The key used when the parsed option is passed to your command’s `action`. Use camelCase (e.g. `dryRun`, `env`). It must match the attribute name that Commander derives from the flags—so for `-d, --dry-run`, Commander uses `dryRun`; your `name` must be `dryRun` as well. If the given name does not match the name generated by Commander, an error will be thrown when generating the ZincOption.

**Flags**: The option’s CLI flags for Commander (e.g. `-d, --dry-run`, `-e, --env`)

**Description**: Shown in `--help` and, when no custom `inquiry` is set, used as the prompt message when Inquirer asks for the value interactively.

**Inquiry**: Optional string to use when prompting the user for input via Inquirer

**Silent**: When passed as true, Inquirer step is skipped and only a value passed via command line argument is used.

**Default**: Optional default value to use for a ZincOption. The type requirements for the default value vary depending on the option (i.e. Boolean options must have default values of type `boolean`), but all ZincOptions can take a default value.

### Input option

Free-form input, validated by a Zod schema. Use for strings, numbers, etc.

#### Specific Args

These are args that are specific to Input options.

**Schema**: This is the zod schema used to parse, transform, and validate a value given for the option. As both Commander and Inquirer, at least in the Zinc implementation, will always produce `string` values, the schema given must be able to take an `input` of `string`. This means instead of using `z.number()` you must use `z.coerce.number()`.

#### Examples

```ts
const countOption = ZincOptionCreators.input({
  name: 'count',
  flags: '-c, --count <count>',
  description: 'Number of items',
  schema: z.coerce.number(),
});

// Optional: allow undefined
const optionalCount = ZincOptionCreators.input({
  name: 'count',
  flags: '-c, --count [count]',
  description: 'Number of items',
  schema: z.coerce.number(),
}).optional();

// With default (no prompt when default applies if silent)
const countWithDefault = ZincOptionCreators.input({
  name: 'count',
  flags: '-c, --count [count]',
  description: 'Number of items',
  schema: z.coerce.number(),
  default: 10,
  silent: true, // skip inquirer when default is used
});

// Supports more complicated schemas
const possibleCsvColumnHeaderSchema = z.enum(['header1', 'header2', 'header3']);
const csvColumnHeaderOption = ZincOptionCreators.input({
  name: 'csvHeaders',
  flags: '--csv-headers',
  description: 'Csv Column Headers',
  schema: z
    .string()
    .transform((csvString) => csvString.split(','))
    .pipe(z.array(possibleCsvColumnHeaderSchema)),
});
```

**Important:** The `name` must match the long-flag name that Commander derives (camelCase). For example `--dry-run` becomes `dryRun`, so use `name: 'dryRun'`.

### Boolean option

Yes/no flag. Always has a value (defaults to `false` if not provided). Supports `.default(value)` and `.silent()`. No Schema can be supplied as it automatically applies `z.stringbool()` schema.

#### Examples

```ts
const dryRunOption = ZincOptionCreators.boolean({
  name: 'dryRun',
  flags: '-d, --dry-run',
  description: 'Dry run',
  default: false,
});

// Silent: only settable via CLI, no inquirer prompt
const silentDryRun = ZincOptionCreators.boolean({
  name: 'dryRun',
  flags: '-d, --dry-run',
  description: 'Dry run',
}).silent();
```

### Select option

Choose from a fixed list of options.

#### Specific Args

These are args specific to Select zinc options.

**Schema**: Schema applied to parse, transform, and validate given value for the zinc option. Usually an enum of valid options.

**Choices**: The choices array has a type of `InquirerSelectConfig['choices']` which is pulled directly from the Inquirer library and is how choices are defined for their `select` prompt. If a choice is present that the given `schema` would fail to parse, a `SelectChoiceInvalidError` is thrown on Zinc option creation.

#### Examples

```ts
const envChoices = [
  { name: 'Production', value: 'prod' },
  { name: 'Staging', value: 'stage' },
] as const;

const envOption = ZincOptionCreators.select({
  name: 'env',
  flags: '-e, --env [env]',
  description: 'Environment',
  schema: z.enum(['prod', 'stage']),
  choices: [...envChoices],
});

// Optional or with default
const envWithDefault = ZincOptionCreators.select({
  name: 'env',
  flags: '-e, --env [env]',
  description: 'Environment',
  schema: z.enum(['prod', 'stage']),
  choices: [...envChoices],
  default: 'stage',
  silent: true,
});
```

### Utilities

#### CliInfer

This is a type utility, basically copied from Zod, that allows you to get the inferred output of a zinc option

```typescript

  name: 'env',
  flags: '-e, --env [env]',
  description: 'Environment',
  schema: z.enum(['prod', 'stage']),
  choices: [...envChoices],
});

type InferredOutput1 = CliInfer<typeof envOption>; //  'prod' | 'stage'

const withOptional = envOption.optional();

```

## createCommand (Commands)

Commands are created with **createCommand**. Pass a name, description, an array of options (from ZincOptionCreators), and an `action` that receives the parsed options. Parsed options are fully typed from your option definitions.

```ts
import { Command } from 'commander';
import createCommand from './command-creator';
import { ZincOptionCreators } from './option-creator';
import { z } from 'zod';

const envOption = ZincOptionCreators.select({
  name: 'env',
  flags: '-e, --env [env]',
  description: 'Environment',
  schema: z.enum(['prod', 'stage']),
  choices: [
    { name: 'prod', value: 'prod' },
    { name: 'stage', value: 'stage' },
  ],
});

const dryRunOption = ZincOptionCreators.boolean({
  name: 'dryRun',
  flags: '-d, --dry-run',
  description: 'Dry run',
  default: false,
});

const deployCommand = createCommand({
  name: 'deploy',
  description: 'Deploy to an environment',
  options: [envOption, dryRunOption],
  action: async (parsedOptions) => {
    // parsedOptions is { env: 'prod' | 'stage'; dryRun: boolean }
    console.log(
      `Deploying to ${parsedOptions.env}, dryRun: ${parsedOptions.dryRun}`
    );
  },
});

const program = new Command().name('my-cli').addCommand(deployCommand);

program.parse();
```

Behavior:

- Options provided on the command line are parsed and validated with Zod.
- Options not provided are filled by Inquirer prompts (unless the option has a default and is `silent`, or is optional and `silent`).
- The combined result is parsed again with the merged schema; then `action(parsedOptions)` is called.

## Exported types

From the option-creator module you can use:

- `ZincOption`, `ZincOptionArray` – option types
- `ParsedOptions<Options>` – inferred type of the object passed to `action`
- `CliInfer<TOption>` – inferred output type of a single option
- `BuildEnvironmentSchemaFromOptions` – build a Zod object schema from an array of options (used internally by createCommand)

# Development

## Prerequisites

- Node.js
- npm

## Install dependencies

```bash
npm install
```

## Run tests

- **Watch mode** (re-runs on file changes):

  ```bash
  npm test
  ```

- **Single run** (CI-friendly):

  ```bash
  npm run test:run
  ```

Tests use [Vitest](https://vitest.dev). Type-checking is enabled for test files (e.g. `expectTypeOf` and type assertions).

| `npm run build`        | Compile TypeScript (`tsc`)     |
| `npm run typecheck`    | Type-check without emitting    |
| `npm run lint`         | Run ESLint                     |
| `npm run lint:fix`     | Run ESLint with auto-fix       |
| `npm run format`       | Format with Prettier           |
